# Eduardo — голосовой ассистент для macOS

Ассистент постоянно слушает микрофон. Когда в речи встречается слово-триггер
**«Эдуардо»**, всё, что сказано после него, считается командой. Команда
отправляется в DeepSeek API (function calling), модель определяет намерение
и параметры, после чего Python выполняет реальное действие на Mac и
озвучивает результат через `say`.

## Архитектура

```
eduardo/
├── __main__.py        # главный цикл: слушаем -> роутим -> выполняем -> озвучиваем
├── config.py           # ключи из env, пути, константы
├── audio_listener.py   # Vosk (офлайн) + fallback SpeechRecognition/Google
├── llm_router.py        # DeepSeek API, function calling (2 шага)
├── actions.py            # open_application, web_search, open_terminal_and_cd, stop_assistant
├── weather.py             # wttr.in — реальная погода без ключа API
├── tts.py                  # озвучка через `say`
└── sounds.py                # звук пробуждения через `afplay`
```

Как это работает по шагам, на примере "Эдуардо, какая погода в Берлине":

1. `audio_listener` распознаёт речь, находит триггер, отдаёт команду
   "какая погода в Берлине" в главный цикл.
2. `llm_router.route_command()` отправляет её в DeepSeek с описанием
   доступных функций — модель выбирает `get_weather(city="Берлин")`.
3. `weather.get_weather("Берлин")` реально запрашивает wttr.in и получает
   настоящую температуру.
4. `llm_router.generate_final_reply()` отдаёт эти реальные данные обратно
   DeepSeek, и модель формулирует естественный ответ по-русски
   ("В Берлине сейчас 12 градусов, облачно").
5. `tts.speak()` озвучивает ответ через `say`.

DeepSeek никогда не "выдумывает" данные — она только формулирует текст по
тому, что реально вернула функция.

### Безопасность

Модели доступны только 5 фиксированных функций с типизированными
параметрами — никакой функции "выполнить произвольный shell" не существует
в принципе, поэтому голосовое подтверждение для них не требуется. Для
команды "открой терминал и перейди в..." путь проверяется на существование
в Python до открытия Terminal, а сама AppleScript/shell-команда
экранируется на двух уровнях (`shlex.quote` + экранирование строкового
литерала AppleScript), что исключает инъекции.

## Установка

### 1. Системные зависимости (через Homebrew)

```bash
brew install portaudio
```

`portaudio` нужен для сборки `PyAudio` (используется запасным
распознавателем речи через микрофон).

### 2. Python-зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Модель Vosk (офлайн-распознавание русской речи)

1. Скачайте небольшую русскую модель, например `vosk-model-small-ru-0.22`,
   со страницы [alphacephei.com/vosk/models](https://alphacephei.com/vosk/models).
2. Распакуйте архив и положите папку сюда:
   ```
   MyTalkingEduardo/models/vosk-model-small-ru-0.22/
   ```
   Либо укажите свой путь через переменную окружения `VOSK_MODEL_PATH`.

Если модель не найдена, ассистент напечатает понятную инструкцию и
автоматически переключится на запасной режим — распознавание речи через
Google Web Speech API (библиотека `SpeechRecognition`, требует интернет).

### 4. Ключ DeepSeek API

```bash
cp .env.example .env
# откройте .env и впишите свой ключ, либо просто:
export DEEPSEEK_API_KEY=sk-...
```

Ключ берётся из переменной окружения `DEEPSEEK_API_KEY` — в коде он не
хранится.

## Разрешения macOS

При первом запуске macOS запросит:

- **Микрофон** — обязательно для распознавания речи (Системные настройки →
  Конфиденциальность и безопасность → Микрофон → разрешить терминалу/Python).
- **Автоматизация (Automation)** — нужна для команды "открой терминал", так
  как она управляет Terminal.app через AppleScript (Системные настройки →
  Конфиденциальность и безопасность → Автоматизация → разрешить доступ к
  Terminal для приложения, из которого запущен Python).

Без этих разрешений соответствующие функции будут возвращать понятную
ошибку вместо падения программы.

## Запуск

```bash
source .venv/bin/activate
export DEEPSEEK_API_KEY=sk-...
python -m eduardo
```

## Примеры голосовых команд

- «Эдуардо, открой Safari»
- «Эдуардо, открой заметки»
- «Эдуардо, какая погода в Москве»

## Тесты

Все внешние вызовы (`subprocess`, DeepSeek API, HTTP-запросы к wttr.in)
замоканы — тесты запускаются без macOS и без реальных API-ключей:

```bash
pip install -r requirements.txt
pytest tests/ -v
```

## Известные ограничения

- Работает только на macOS (используются `open`, `say`, `afplay`,
  `osascript` — на других ОС соответствующие функции возвращают
  понятную ошибку вместо действия).
- Слово-триггер распознаётся по нескольким вариантам написания
  ("эдуардо", "едуардо", "eduardo" и т.п.), но реальное качество
  распознавания зависит от модели Vosk и микрофона — в шумной обстановке
  триггер может не сработать.
- Запасной режим (Google Web Speech API) требует постоянного подключения
  к интернету и имеет неофициальные лимиты запросов.
- `get_weather` использует wttr.in — бесплатный сервис без ключа, но без
  гарантий SLA; иногда может быть недоступен или медленно отвечать.
- Команда "открой терминал и перейди в..." ищет папку только внутри
  `~/Documents`, если не указан абсолютный путь или путь с `~`.
- `web_search` открывает результаты в браузере по умолчанию, а не
  возвращает их голосом — сам ассистент не читает содержимое страниц.
